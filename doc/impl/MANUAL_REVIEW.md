# Manual Evidence Map

The ready-built user manual and its LuaLaTeX sources describe bounded native
workflows, not every installed utility. This map connects those claims to
maintained tests; it is not an editorial work log or a historical-software
certification.

The explicitly refreshed versioned PDF includes the completed idle/partial-
input reconnect and failure-preservation procedures, with no internal-document references.
Changed operating pages were visually reviewed; fonts are embedded and final
TeX output has no box overflow or unresolved references. The task-navigation
table is compacted to keep the supported workflow links together. Future
source changes require another explicit PDF build/layout review.

## Evidence policy

- Architectural manuals explain intent, units and version differences.
  OCR text must not silently override verified guest syntax.
- A test establishes the operations it checks, not every option of a tool.
- File contents and binary strings can establish inventory or identity,
  not safe execution or a complete calling convention.
- Frontend protocol tests do not establish a compatible guest driver.
- Successful reproduction establishes a source/binary pair, not vendor
  authenticity or redistribution permission.

[Test Fixtures](TEST_FIXTURES.md) is the detailed authority for assertions and
scope limits. In particular, it retains process-removal free markers, independent
descriptor/parent comparisons, the misleading montest peripheral label,
auxiliary versus main catalog sizes and specific IX-disabled recovery evidence.

The historical RC multiprogramming-system and SLANG manuals explain different
software versions. Sections 17.28--17.29 distinguish historical day-first
newdate/date inquiry from the supplied monitor's year-first setting command.
SLANG section 4.6 explains assembly reports/result status, but failed assemblies
still require the native partial-result checks. Original OCR files are reference
material, not runtime dependencies.

## Maintenance

Keep example prerequisites, input context, expected result and cleanup explicit.
Tutorial files under doc/usermanual/examples/ match the relevant test inputs.
Do not promote untested inventory into operating recipes without a bounded
native check. Broader software/monitor work remains on the
[Roadmap](PORTING_PLAN.md).

Source-only checks are described in [Development](DEVELOPMENT.md#distribution-and-documentation).
They validate structure and references, not rendered layout. The versioned PDF
has been built and visually reviewed; future source changes require a separately
requested PDF update and layout review. No intermediate PDFs, renderings,
trial transcripts or review timelines belong in this directory.
